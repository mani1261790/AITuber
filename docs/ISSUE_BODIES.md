# GitHub Issue登録原稿

この文書の各 `##` 節を、同じ番号のGitHub Issue本文として登録する。正本は [REQUIREMENTS.md](../REQUIREMENTS.md)、順序は [IMPLEMENTATION_PLAN.md](./IMPLEMENTATION_PLAN.md) とする。

## 1. 開発基盤とアーキテクチャ境界を作る

**Milestone:** M0 基盤  
**Labels:** `phase: foundation`, `area: platform`, `priority: p0`

TypeScript、React、常駐Node.jsを使うワークスペースを作り、教室、運営、サーバー、契約、講義、表示、教材、Provider、保存の境界を分ける。特定Webフレームワークの型をドメイン契約へ持ち込まない。

### 受入条件

- `apps/classroom`、`apps/operator`、`apps/server` と必要な `packages/*` を作る。
- lint、型検査、単体試験、ビルドを一つのコマンド群で実行できる。
- `.env.example` にLLMとFish Audioの設定名だけを記載し、秘密値を含めない。
- ローカル起動手順、対応Node.js版、構成判断をREADMEまたはADRへ記録する。

**対応要件:** NFR-10

## 2. Course Packageの契約と検証を実装する

**Milestone:** M0 基盤  
**Labels:** `phase: foundation`, `area: content`, `priority: p0`
**Depends on:** #1

Course Package、Teaching Unit、表示場面、意味ID、確認問題、事前補足、出典をランタイムで検証できる版付き契約として定義する。

### 受入条件

- JSON Schema等で未知フィールド、欠落、過大配列、不正参照を拒否する。
- Course Packageの版と内容ハッシュを保持し、利用可能版を直接変更できない。
- Teaching Unitの前提・事後条件、表示差分、発話、字幕、省略可否を表現できる。
- 数式・画像・文章に安定した意味IDを割り当てられる。

**対応要件:** FR-01, FR-03, FR-04, FR-05

## 3. SQLiteイベント保存・スナップショット・再生を実装する

**Milestone:** M0 基盤  
**Labels:** `phase: foundation`, `area: data`, `priority: p0`
**Depends on:** #1, #2

単一の状態更新元から、授業イベントとスナップショットをSQLiteへ保存し、停止や再接続後に同じ状態を再構築できるようにする。

### 受入条件

- イベントがID、session ID、教材版、epoch、seq、時刻を持つ。
- 重複イベントを再送しても状態を二重更新しない。
- スナップショットと後続イベントから状態を再生できる。
- DB書込み失敗時は未記録のまま進行しない。
- WALを含む整合したバックアップ手順を試験する。

**対応要件:** FR-17, FR-18, FR-25, NFR-08

## 4. 決定的な講義状態機械を実装する

**Milestone:** M0 基盤  
**Labels:** `phase: foundation`, `area: runtime`, `priority: p0`
**Depends on:** #2, #3

AIやブラウザーへ依存せず、開始、教授、確認、分岐、再接続、停止、復旧、終了を純粋な状態遷移として実装する。

### 受入条件

- 要件9.1の全状態と許可された遷移を実装する。
- 音声完了通知まではTeaching Unitを完了にしない。
- 停止時にepochを更新し、古い非同期結果を拒否する。
- 固定イベント列の再生で同じ状態と次アクションを得る。
- 待機状態からProvider呼び出しを発生させない。

**対応要件:** FR-05, FR-06, FR-17, FR-23, FR-25

## 5. 安全な表示・板書・意味IDポインタを実装する

**Milestone:** M0 基盤  
**Labels:** `phase: foundation`, `area: presentation`, `priority: p0`
**Depends on:** #2

Course Packageの許可済みテンプレートだけから文章、画像、数式、構造化板書を描画し、意味IDで対象を指せるステージを作る。

### 受入条件

**対応要件:** FR-04, NFR-04, NFR-05, NFR-07

## 6. 3本の検証用Course Package fixtureを作る

## 8. Fish Audio音声・字幕・取消しを統合する

**Milestone:** M1 決定的な縦切り  
**Labels:** `phase: vertical-slice`, `area: audio`, `priority: p0`

### 受入条件

- Provider、モデル、音声、辞書版、言語、文章を含むキャッシュキーを使う。
- TTS失敗時は字幕で継続し、測定した初音声時間と長文連続性を記録する。

**対応要件:** FR-14, FR-17, NFR-01, NFR-03, NFR-04

## 10. LAN教室参加・同期・再接続を実装する

**Milestone:** M1 決定的な縦切り  
**Labels:** `phase: vertical-slice`, `area: classroom`, `priority: p0`
**Depends on:** #3, #7

同じLAN上の端末が短い教室コードで参加し、授業状態を追従できるようにする。

### 受入条件

- 1〜5人がアカウントなしで参加し、セッション限定匿名IDを得る。
- WebSocket切断後にsnapshotとseqから追従し、過去音声を再生しない。
- 一端末の切断で教室全体を停止しない。
- 学習者はシステム設定、教材管理、他人の回答へアクセスできない。
- LAN外へ公開しない既定設定と起動時のURL表示を用意する。

**対応要件:** FR-16, FR-18, NFR-02

- 学習目標、前提、人数、待ち時間、残り時間を優先判断に使う。

## 14. ライブ補足・つなぎ・本編再接続を実装する

**Milestone:** M2 自動教材と適応講義  
**Labels:** `phase: automation`, `area: runtime`, `area: ai`, `priority: p0`
**Depends on:** #4, #8, #11, #13

未想定質問に対する補足を自動生成・自動審査・自動再生し、未完了の本編へ安全に戻す。

### 受入条件

- 教材内検索を優先し、授業中のWeb検索を行わない。
- 出典、意味ID、内容、板書、決定的計算を検査する。
- 不合格時は1回だけ再生成し、再失敗時は保留して本編を続ける。
- 前提非依存なら本編を進め、依存時や連続補足時は事前候補優先のつなぎを使う。
- 未完了単位を落とさず、訂正前表示を戻さずに本編へ再接続する。

**対応要件:** FR-09, FR-10, FR-11, NFR-03

- 顔、視線、表情、沈黙を取得または判断材料に使わない。
- 補足後の回答を新しい証拠として記録する。

**対応要件:** FR-12, FR-13, FR-24

## 16. 授業後の保留回答・結果・任意アンケートを実装する

**Milestone:** M3 MVP完成  
**Labels:** `phase: mvp`, `area: classroom`, `priority: p1`
**Depends on:** #13, #14, #15

授業中に扱えなかった質問を自動処理し、授業結果と任意アンケートを提供する。

### 受入条件

- 授業末に時間があれば重要な保留質問へ回答する。
- 残りは授業後に自動生成・審査し、合格回答だけを閲覧可能にする。
- 説明済み、未完了、回答済み、未確認、保留、訂正を分けて表示する。
- 固定評価2問と自由記述を任意表示し、確認問題の証拠と分離保存する。
- 不合格回答は未回答理由を残す。

**対応要件:** FR-19, FR-20, FR-24

## 17. データ保持・費用予約・入力防御を完成させる

**Milestone:** M3 MVP完成  
**Labels:** `phase: mvp`, `area: security`, `area: data`, `priority: p0`

- コメント元、利用者ID、対象箇所の不足を明示して質問へ変換する。
- スパム、連投、外部命令を既存の入力防御と優先キューで制御する。
- 配信連携障害で講義実行核が停止しない。
