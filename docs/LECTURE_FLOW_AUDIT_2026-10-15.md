# PDF教材から授業実行までの監査

調査日: 2026-10-15。対象: main `c8572a760db5b354451968a02269cdaef845baca`。
対象フロー: PDF登録 → Course Package生成・審査・保存 → Unitごとの発話・動作・板書生成 → Fish Audio → 教室で順次実行。

**判定: 部品の多くは実装済みだが、このフロー全体を正常と判定できない。実授業の品質評価へ進む前に、以下の接続漏れを解消する必要がある。**
この監査では製品コードの変更・デプロイは行っていない。質問の分類・授業後の運用は今回の主対象外。

## 実装済みの範囲

| 工程 | 確認した実装 | 証拠の限界 |
| --- | --- | --- |

| パッケージ生成 | LLM生成、スキーマ・参照検査、別コンテキストで9項目審査、不合格時修正、合格後available | 実LLMによる今回のPDF生成は未実施 |
| 保存・読み込み | 作成ジョブとパッケージを保存し、合格教材を講義サービスに登録。再起動時も再登録 | Cloudflareの現在の教材内容は未確認 |
| 授業中の生成 | Unitの要点・説明順序・言い回し・前の発話等を渡し、1〜3のbeatを生成 | 生成失敗時は参考台本に置換される |

## 修正が必要な箇所

### 1. 元のPDFを投影していない（優先度: 最優先）

- `apps/server/src/source-ingestion.ts:37` はPDF全体を `mergePages: true` で抽出する。
- `packages/contracts/src/course-package.ts` のSceneには元PDFのページ指定がない。
- `apps/classroom/src/lesson-texture.tsx` はタイトルとsemanticTargetsをHTMLとして組み直して画像化している。元PDFページの画像化ではない。
- 原本保存から、教材ページの配信・描画・Unitとの対応付けへつなぐ経路がない。

影響: スライドPDFを登録しても元の配置、図表、改ページで授業できない。元教材を投影するという合意に未達。

必要な修正: ページ単位の出典・Unit/Scene対応をパッケージに保持し、原本ページを画像化して投影する。指差し先の領域も同じページ座標へ対応させる。

### 2. PDF内の図・画像を生成器に渡していない（最優先）

PDF経路でLLMに渡すのは抽出文字列のみ。画像アップロード経路はあるが、PDFページ内の画像・グラフはその経路に入らない。抽出文字がないPDFは `source did not contain extractable text` で失敗する。

影響: グラフ主体の教材、画像化された数式、スキャン教材の理解が欠ける。出典審査も同じ不足した情報を参照するため、審査合格だけで原本との一致を保証できない。

必要な修正: PDFページ画像とページ別テキストを授業前の生成・審査へ入力する。文字が取れないページも原本画像を使えるようにする。

### 3. 接続失敗が「正常に進んだ授業」に見える（最優先）

- `lesson-director.ts` はLLM未設定・タイムアウト・検証不合格時に `referencePlan` を返す。
- `fixed-lecture-service.ts` は音声provider/voice未設定時に `mode: test` として既定2秒で進行する。
- TTS失敗時は `caption-fallback` で進むが、教室字幕は初期OFFで、フォールバック時に自動表示されない。
- 管理画面には生成元 `generated/reference` と失敗理由を継続監視する表示がない。設定済み表示も実接続成功とは別。

必要な修正: 本番開始前の実接続確認と、模擬実行/劣化動作の明確な区別。失敗時の停止・再試行・字幕で続行という扱いを一貫させ、無音のまま進行しないようにする。

### 4. 再生完了を待つ契約が完全ではない（高）

`fixed-lecture-service.ts:69-85` は音声durationにFish Audio用850msの間を加えたタイマーを基準にする。クライアントは500msごとに残時間とendedを報告するが、サーバーは期限を延長するだけで、延長上限は当初期限+30秒。

影響: 通常再生への配慮はあるが、長いバッファ待ち・自動再生ブロック時にも時間上限で次へ進める。複数視聴者は全員同じ期限を延長でき、誰の再生を授業進行の基準にするか明示されていない。音声の重複が今回再現したという意味ではなく、完了前進行を排除できていない。

必要な修正: 進行基準となる再生状態を定義し、再生完了→間→次actionを保証する。未再生・切断時の扱いを通常完了と分離する。

### 5. スクリーンを下ろす動作は本番のactionに未接続（高）

`fixed-lecture-service.ts` の `show_slides` はsurfaceを切り替えて700ms待つだけ。`vrm-avatar.tsx` の本番用propActionはdrawing時のwriteを生成するが、show_slidesでは紐を引くscreenアクションを生成しない。スクリーンはprojecting値へ自動補間する。

板書開始時のスクリーン収納はwriteの前処理として接続済み。一方、投影開始・板書後の再投影・Unit終了時の再投影は別扱い。モーションラボで引く動作が動くことは本番の接続証明にならない。

必要な修正: 投影・収納を共通のstage actionに統合し、動作完了を待つ。自動昇降を選ぶ場合も、表示準備完了前に発話を始めない。

### 6. LLMのカメラ指定が実カメラへ反映されない（中）

生成結果は `camera: lecture/material` を持ち、サーバーもdirectionに保存するが、`vrm-avatar.tsx` は `selectClassroomCamera` と `applyClassroomCamera` で自動選択し、direction.cameraを読まない。

必要な修正: 自動の遮蔽回避を維持しつつ指示を選択条件へ反映するか、効果のない出力項目を生成契約から外す。

### 7. 授業前の「進め方」が必須保証されていない（中）

作成プロンプトは各UnitのteachingPlan.keyPoints/explanationFlowを要求するが、契約上teachingPlanはOptional。決定的レビューでも欠落を検査しない。既存教材との互換性は必要だが、新規PDF生成教材まで計画なしで合格できる。

必要な修正: 新規生成物については授業計画の存在・要点・順序を合格条件とし、古い教材の互換読み込みとは分ける。

### 8. 板書プロンプトと現行レイアウトが不一致（中）

`apps/server/src/blackboard-markdown.ts` は「見出しと独立数式を自動中央寄せ」と指示する。現行 `board-markdown.tsx` / `styles.css` は左上の固定原点と左揃え・インデントで描画する。

必要な修正: LLMへの配置説明を現行描画仕様へ合わせ、実LLMのfew-shot出力を本番の描画・書字速度・発話開始まで通して確認する。

## 修正・実授業確認の順序

1. PDFページ画像・ページ別入力・出典対応・投影を一体で接続する。
2. 新規教材のteachingPlan保証と板書プロンプトを整合させる。
3. 本番接続確認・失敗表示・音声完了待機を整える。
4. スクリーン動作の本番接続、カメラ指示の扱いを整える。
5. 短い実スライドPDFで登録から合格まで実LLMを通す。原本の図・数式・ページ順との一致を人が確認する。
6. その保存済みパッケージで実授業を開始。各Unitの `lesson.direction-planned.source=generated`、Fish Audio実音声、stage完了、板書、次Unitへの遷移を記録する。
7. 音声ブロック・読込遅延・再接続も確認後、ユーザーが授業を視聴してフィードバックする段階へ進む。

受入条件: 原本を投影する、実生成で進む、無音の見せかけ進行がない、読み終わってから次へ進む、板書・スクリーンの完了を待つ、指差しと表示が対応する。この全てが同じ授業実行で成立すること。
