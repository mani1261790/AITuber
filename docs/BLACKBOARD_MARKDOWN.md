# 台本と同時に生成する板書

新規の板書にSVG専用モデルを使わない。Unit台本の各beatとライブ補足の生成結果に `blackboardMarkdown` を含め、同じLLM応答で発話文と板書を生成する。nullならスライド、文字列なら独立した黒板を全面更新する。保存済みSVGのみ表示互換を残す。

## 記法とfew-shot

```markdown
# 平方完成
◎ **同じ値を足して引く**
$$x^2-4x+3=(x-2)^2-1$$
→ 頂点は $(2,-1)$
```

- `#` / `##`：見出し、改行：次の板書行
- `**強調**`：黄色。`◎`、`→`などをそのまま表示
- `$...$`、`$$...$$`：TeX。式の入力は一行で指定
- `-` / `*` の行頭箇条書き：「・」

最大8非空行・各行80文字・全体700文字。推奨は3〜5行、通常の日本語行は24文字程度。HTML・画像・リンク・コードブロックは禁止。

`packages/contracts/src/board-examples.ts` に高校数学・大学数学・歴史の3例を保持する。サーバーの共通指示に入力と出力の組として含める。モーションラボも同じ例を使用する。別途、スライドを使うnullの例も指示に含める。

## 表示とタイミング

1. フォント読み込みとTeX組版を待ち、板書を1280×720の画像に一度だけ描く。
2. スクリーンが出ていれば、リングを掴んで約30cmの短い引きを行い、離してスクリーンを格納する。
3. 先生が黒板へ移動・回転し、腕を上げてから表示開始。書字の仕草をループする。
4. 通常文字は約0.15秒／文字、改行間は0.35秒。数式は0.8〜3秒のまとまりで、完成した組版を一度に表示する。700文字など上限付近の板書は表示を最大30秒へ圧縮する。
5. 最後の表示後0.45秒待ち、1.1秒かけて腕を下ろす。これで板書完了を通知。
6. 台本の立ち位置へ戻り、指差し準備を終えてから発話する。書きながら話す方式にはまだしていない。

本文は既存のZen Kaku Gothic New（42px）、見出し48px、数式はKaTeX。1120×560の安全域へ全体を等比縮小し、板書内スクロールは設けない。組版済み文字の矩形を順次表示するため、表示途中に改行位置や分数の配置は変わらない。手の軌跡で図を描いたり、筆跡そのものを生成したりはしない。

授業はクライアントの完了通知まで発話を待つ。進捗通知がある板書の待機は延長するが最大90秒。通知が12秒途切れれば、見えていない板書の説明へ進めず既存の失敗経路へ戻す。ライブ補足の生成・審査の20秒制限は維持し、生成後の板書動作には別に90秒の猶予を設ける。

## 動作の確認

モーションラボの「黒板に書く」は書く仕草だけを「書き終える」まで繰り返し、表示内容を追加しない。スクリーンが出ていれば先に引いて戻す。「板書・発話の確認」では3例から選び、Markdownを編集して「板書を開始」できる。これは授業と同じ表示・動作・完了通知を使用する。説明文の開始タイミングを表示するが、確認画面ではTTSを再生しない。

## 実LLMでのfew-shot確認

管理者専用の `POST /api/settings/llm/board-preview` に `{ "example": 0 }`〜2を送ると、保存済みLLM設定・利用予算を使って生成する。授業や教材を作らず、few-shotにない高校数学・大学数学・生物の3題で適用を確認する。返却は板書・発話文・モデル・使用量・遅延のみ。APIキーは返さない。

GitHub Actions の **Verify board few-shot on configured LLM** は手動実行専用で、最大3回だけ生成し、結果を7日間のArtifactに保存する。通常のデプロイで有料生成は実行しない。生成の成否と、数式の正しさ・言い回し・最終画面の読みやすさは別に確認する。
