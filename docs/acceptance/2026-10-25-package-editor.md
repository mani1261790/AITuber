# 教材パッケージと編集画面

## 実装

教材作成の公開ゲートに全体台本生成・全体審査・全文の読み生成と審査を移した。CoursePackage.performance に順序付きの発話、スライド/板書指定、原文と読みの対応を保存する。通常の講義では埋め込まれた台本を再生し、台本生成を呼ばない。質問後の未再生部分への限定的な差分適用は維持する。

教材一覧からパッケージ編集を開ける。台本、説明順、スライド/板書、読み、確認問題、正解条件・解説、誤答傾向を編集できる。PDFはPDF.jsのcanvasで表示する。下書き保存と公開を分け、公開前に教材・全体台本・読みを審査する。変更された発話の読みは再準備する。音声キャッシュは読みの内容を含むハッシュで区別する。

下書きは公開版と別に永続化し、更新競合をrevisionで拒否する。公開は新しいversionとcontentHashを付与する。既存の授業は開始時の公開版と読みを保持する。旧教材は編集画面で準備・公開してから開始する。完成済み台本と講義時間の不一致を許可しない。公開中の停止、15分の上限、再起動による中断、書き込み保護停止を扱い、自動再試行し続けない。

## 検証

- ローカル: 100ファイル609テスト成功。教材作成が台本準備完了前に公開されないこと、準備失敗時の非公開、下書き保存、競合拒否、審査失敗時の公開版保持、公開版の再起動復元、準備済み台本のLLM呼び出しなし再生を含む。
- server/operator/cloudflareの型検査。
- Playwright: 実HTTPのローカルAPIで教材名編集→下書き保存→公開→再読込。AI審査は固定応答のfixtureであり、実ChatGPT審査ではない。
- デスクトップ・390px幅の画面記録: output/playwright/package-editor-20261025。
- Workerローカル: 認証、origin検査、SQLite、WebSocket、PDF、日本語教材、再起動・再接続。
