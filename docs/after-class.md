# 授業末と授業後の処理

## 授業末

最後のTeaching Unitが終わった時点で20秒以上残っていれば、質問キューのうち未処理で最も優先度が高い1件を`answer-now`へ戻す。回答は通常のライブ補足として生成・審査・再接続する。完了後にも時間があれば次の1件を選ぶ。20秒未満、既に保留済み、またはライブ補足が2回不合格になった質問は授業後へ送る。

## 授業後回答

講義が`FINISHED`へ移ると、回答済みでない質問を受付順に自動処理する。授業中の音声再生は行わない。

1. 質問時のCourse Package版、scene、意味IDを固定したまま教材内の関連箇所を抽出する。
2. 教材を優先して短い回答候補を生成する。授業中と同じくWeb検索は行わない。
3. 別コンテキストが出典、内容、安全性を審査し、サーバーも出典IDと文字数を検査する。
4. 不合格理由を渡して1回だけ再生成する。
5. 合格した回答だけを`available`として教室へ返す。不合格、LLM未設定、Provider失敗は`unanswered`とし、候補本文を公開せず理由を残す。

候補、審査、失敗理由は`after_class_answer_attempts`、公開状態は`after_class_answers`へ保存する。教室画面は準備中、授業後の回答、未回答を区別し、未回答時は理由を表示する。

## 結果

結果画面は、説明済み数、未完了数、回答済み質問数、保留・未回答数、訂正数を別々に表示する。[学習証拠](./learning-evidence.md)の5状態も学習目標ごとに表示し、未確認を自動で習得済みにしない。訂正があれば訂正後の内容を一覧に残す。

## 任意アンケート

アンケートを送らなくても結果は閲覧できる。送る場合は次の固定2問を1〜5で評価し、2000文字以内の自由記述を任意で添える。

1. 質問した箇所を理解しやすくなったか
2. 補足後、本編へ自然に戻れたか

回答は`after_class_surveys`へ保存する。確認問題や自己申告を持つ`learning_evidence`とは結合せず、学習状態の判定にも使わない。同じ参加者が再送した場合は、その授業に対する本人の回答だけを更新する。
