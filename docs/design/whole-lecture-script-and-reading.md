# 全体台本と全文の読み処理

2026-10-24のユーザー指摘に基づく設計変更案。現状調査と実装要件を記録する。以下は未実装であり、revision23の稼働機能ではない。

## 現状の問題

course-authoring-service.tsはspeechTextを参考説明として生成し、最終台本を作らないよう指示している。lesson-director.tsは単元ごとに直前の発話を渡して書き直す。このため全体を編集する段階がなく、接続の指示を積み重ねても、重複・不自然な接続・講義中の生成待ちが残る。

fixed-lecture-service.tsのapplyPronunciationDictionaryは登録語だけを置換する。speech-caption.tsは読みから元の表記へ逆置換する。未知語や文脈による読み分けを網羅できず、同じ読みの異なる表記も逆置換では区別できない。

## 目標となる処理

1. 教材全体、対象者、説明順、所要時間、ペルソナを入力し、講義を一本の説明として執筆する。冒頭・展開・確認問題・まとめまでを見通して構成する。
2. 台本に安定した節・発話IDと資料ページの参照を付ける。ページ切り替えは台本中の演出位置として指定する。スライド一枚ごとに作文し直さない。黒板が必要な箇所もこの段階で計画する。
3. 全体を審査し、重複・欠落・誤り・不自然な接続がある箇所を差分修正する。審査済みの最終台本を教材版に結び付けて保存する。
4. 全文を対象に読み上げ用表現をまとめて作る。字幕用の原文と対応を保持する。
5. 音声は再生しやすい発話単位で合成し、開始前と再生中に有限の範囲を先読みする。文章の生成単位と音声の合成単位を分ける。
6. 授業中は保存済み台本を再生する。通常の次単元への進行では文章を再生成しない。質問・理解度変化のときだけ補足と未再生範囲の差分を作る。

全体が応答上限に収まる場合は一括生成する。長い場合は共通の全体台本を章単位で執筆し、前後の本文と未説明事項を共有する。最後に章境界を含む全体審査・差分編集を行う。単元を独立に生成して接続文だけ足す方式には戻さない。一括生成が必ず低遅延・低コストとは限らないため、実測で評価する。

## 全文の読み処理

字幕用原文を基準として保持し、英語・略語・固有名詞・数字・単位・記号・式・コードを文脈に応じて読み上げ用表現へ変換する。既知の読み辞書を優先し、未登録語も処理対象にする。同じ語でも文脈で読み分ける場合は出現箇所ごとに対応を保存する。

読み処理は内容の言い換えを目的にしない。数値・単位・否定・コマンド引数・数式が読みの変換で変質していないか検査する。モデルによる読み生成を無検証で正解扱いにせず、重要語の短い試聴や実音声照合で確認する。

発話ごとに原文、読み上げ文、変換箇所の対応、台本版、読み処理版を保存する。字幕は原文の対応箇所を音声時刻へ結び付け、カナからの逆置換を廃止する。新しい質問回答にも同じ処理を通す。

## 差分更新の境界

差分は対象の台本版・発話ID・変更前本文のハッシュを指定し、追加・置換・削除する範囲を明示する。全体の導入・結論との関係を見て修正するが、既に話した部分と再生中の発話は変更しない。影響が広い場合も未再生範囲を対象とする。

質問回答の後に、常に接続文を生成する必要はない。既存台本で自然に再開できるなら変更しない。既に回答した内容の重複や、理解度に応じた説明変更が必要な場合にだけ差分を適用する。

差分を事実・参照ID・必要な語句・前後関係で検査し、読み処理と音声キャッシュは影響箇所だけ更新する。古い版に対する遅延した差分を適用しない。画面・字幕・音声が別の版を使わないよう公開をまとめる。再起動後も保存済み台本と読みを使い、全体を再生成しない。

## 実装と受入検証

CoursePackageとは別に版付きの最終講義台本を保存し、既存教材も講義準備時に全体台本へ変換できるようにする。まず生成・検証・差分・読み対応の契約と保存を実装し、次に再生サービスを保存台本の実行へ切り替える。移行中に既存の参考説明を審査済み最終台本と偽らない。講義中の準備失敗で単元別生成へ黙って戻さない。

Ollama教材で、全体の内容網羅と話し方、読み上げと字幕対応を審査する。通常進行で単元ごとの生成が起きないこと、質問後に変更される範囲が限定されること、変更されない音声の再利用、停止・再起動・古い差分の拒否を検証する。その後、本番で質問・誤答・再回答を含む全編を実音声で確認する。現在の本番書き込み枠の制約は、この構造変更のローカル実装を妨げるものではない。

## 実装状況（2026-10-24 revision24）

初稿の「未実装」は設計記録時点の状態。`whole-lecture-planner.ts`に全体生成・全体審査・差分修正・保存を実装し、ローカルサーバーとCloudflareの本番接続を切り替えた。20単元以内は一括生成し、それ以上は共通の全体教材と既に書いた本文を渡して20単元ごとに作成後、全体を審査する。通常の進行は保存台本を使う。参考説明への暗黙のフォールバックはしない。

初期審査の不合格は変更前ハッシュ付きの差分で1回だけ修正し再審査する。質問後は直近の未再生3単元を変更可能範囲とし、変更不要なら空の差分を保存する。変更した場合は全体を再審査し、変更文だけ読みを準備する。教材共通の元台本とセッション固有の差分適用結果は分けて保存する。

`prepared-readings.ts`は全発話を最大24件ずつまとめて読み処理し、原文連結の完全一致・カナ表現の検査と独立した読み審査を行う。登録語の有無にかかわらず全文を対象とする。本文・読み・出現位置の対応を保存し、音声合成へ読みを渡す。字幕は提供側の実区間時刻から原文へ対応付ける。対応できない音声は推測の時刻で再生せず失敗として扱う。旧セッションの字幕互換処理は残すが、新経路では逆置換しない。

講義準備中は台本・読み・最初の音声が揃うまで授業時間を消費せず、教室の準備完了通知と合わせて開始する。停止後の遅延結果は保存・再生しない。全体準備は最大10分、各LLM接続の制限も維持する。台本と読みは変更時だけ保存し、再起動後に再利用する。別の教材・時間・台本指示・読み辞書を同じキャッシュと誤認しない。

これは実装範囲の記録であり、本番全講義の最終受入完了を意味しない。
