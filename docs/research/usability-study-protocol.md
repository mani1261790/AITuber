# 成人ユーザビリティ評価プロトコル

## 目的と完了条件

成人6〜10人がAITuberの授業へ実際に参加し、参加、質問、切断後の復帰、確認問題、完走を評価する。各参加者は高校教材1本と大学教材1本を体験する。名前、メールアドレス、音声、映像は収集しない。

製品公開準備へ進む条件は次の5点とする。

1. 有効な同意記録を持つ成人が6〜10人いる。
2. 全員が高校教材1本と大学教材「VAEの再パラメータ化」を完走する。
3. 参加、質問送信、再接続、完走の各成功率が90%以上である。
4. 操作しやすさと理解しやすさの中央値が各4/5以上である。
5. 未解消の`critical`または`blocking`が0件である。

数値は少人数評価の合否判定にだけ使い、一般利用者全体への統計的推定とは扱わない。確認問題正答率、質問後の理解、本編復帰の自然さは改善材料として併記する。

## 対象者と割り当て

- 18歳以上
- 日本語のWeb画面を操作できる
- AITuberの開発へ直接関わっていない
- 教育やAIの専門知識は問わない

参加者IDは`p01`から`p10`だけを使い、氏名との対応表を作らない。参加者には撤回用として自分のIDを伝える。

`pnpm study:new -- p01`は教材順を自動で交互にする。奇数IDは高校教材から、偶数IDは大学教材から開始する。高校教材も二次関数とDNA複製を交互に割り当てるため、順序と科目の偏りを抑えられる。

## 実施前の準備

1. [セルフホスト運用](../self-hosting.md)に従って最新版をバックアップ、更新、ビルドする。
2. `pnpm study:ready`を通す。このコマンドが品質ゲート、実LLM、実Fish Audioを順に確認する。実評価では固定テスト音を使わない。
3. 教室端末からLANの教室URLを開けることを確認する。
4. 参加者ごとに`pnpm study:new -- p01`のように空の記録を作る。
5. `pnpm study:record -- p01`を開始する。[同意説明](./usability-study-consent.md)を提示して質問へ答え、対話式CLIへ結果を順に入力する。18歳以上の確認または同意が得られなければ、記録は変更されない。
6. 自由記述には氏名、所属、連絡先、健康情報など個人を特定しうる情報を書かない。

## 1人あたりの進行

所要時間は35〜45分を目安とする。説明を増やして成功へ誘導しない。参加者が止まった場合は「今やろうとしていることを教えてください」とだけ尋ね、具体的な操作を教えた回数を`assistanceCount`へ記録する。

### 導入 — 3分

1. これは製品の評価であり、参加者の能力試験ではないと伝える。
2. いつでも中止できることを確認する。
3. 思ったことを口に出してもらってよいが、録音はしない。

### 教材1 — 12〜17分

1. 教室URLと教室コードだけを渡し、自力で参加してもらう。
2. 講義を視聴し、疑問を一つ質問欄から送ってもらう。質問内容は指示しない。
3. 質問の受付または補足を確認後、教室タブを閉じ、同じ教室URLを再度開いて復帰してもらう。
4. 確認問題へ回答し、授業終了画面まで進んでもらう。
5. 画面内の任意アンケートへ回答してもらう。
6. 開いたままの記録CLIへ教室コード、4タスクの成功と介助回数、確認問題の正誤、4つの1〜5評価を入力する。

### 教材2 — 12〜17分

教材1と同じ手順を、もう一方の教育段階の教材で繰り返す。

### 終了 — 5分

「特に困った場面」「理解しにくかった場面」「使い続けるうえで妨げになる点」を尋ねる。観察事項は300文字以内で個人情報を除いて`incidents`へ記録し、参加者IDを伝える。

## 記録基準

タスクは、目的の状態へ到達したときだけ`success: true`にする。自力で達成できなくても、介助後に到達した場合は`success: true`とし、介助回数を1以上にする。到達できなかった場合は`false`にする。

4つの評価は各セッション終了時に1「まったくそう思わない」から5「強くそう思う」で尋ねる。

- `operationEase`: 必要な操作を迷わず行えた
- `contentClarity`: 講義内容を理解しやすかった
- `questionHelpfulness`: 質問した箇所を理解しやすくなった
- `rejoinNaturalness`: 補足後または再接続後、本編へ自然に戻れた

発見事項の重大度は次で固定する。

| 重大度 | 判定 |
|---|---|
| `critical` | データ消失、秘密漏えい、誤った学習内容を確定表示するなど直ちに利用を止める問題 |
| `blocking` | 参加、質問、再接続、完走のいずれかを介助しても達成できない問題 |
| `major` | 達成できるが複数人が迷う、理解を大きく妨げる問題 |
| `minor` | 達成と理解を妨げない改善点 |

問題を修正したらGitHub Issue番号を記録し、同じ失敗操作を再実施して成功した場合だけ`resolved`にする。

## 集計と公開判断

```sh
pnpm study:status
pnpm study:summarize
```

`study:status`は完了記録数と不足項目を表示する。`study:summarize`は6〜10人の完全な記録だけを受け付け、`.data/usability-study/summary.md`へ集計と公開ゲート判定を書く。生の参加者IDや自由回答は集計へ出さず、非特定化した発見事項だけを載せる。

公開ゲート未達または未解消の致命的・公開阻害事項があれば、製品公開判断を「保留」とする。修正と再検証後に記録を更新して再集計する。最終集計は個人を特定できる内容を再確認して`docs/acceptance/`へ保存する。

## 撤回と削除

参加者が撤回を希望した場合は、参加者IDを受け取り次を実行する。

```sh
pnpm study:delete -- p01
```

アプリ内の授業、質問、回答、アンケート生データは既定で7日後に自動削除される。研究用JSONは外部送信せず、ローカルの`.data/usability-study/raw/`にmode 600で保存する。最終集計を確認したら、最後の参加者の実施から7日以内に次を実行する。

```sh
pnpm study:delete-raw
```

このコマンドは`summary.md`が存在する場合だけ全生記録を削除する。集計後に残すのは人数、比率、中央値、非特定化した発見事項、公開判断だけとする。バックアップに研究用rawを含めた場合も同じ期限で削除する。
