# 確認問題、学習証拠、能動的な補足

## 証拠の境界

MVPは、学習者が明示的に行った次の入力だけを保存する。

- 対象を固定した質問
- 確認問題への回答
- 「わかった」「もう一度」「助けて」の自己申告
- 質問対象の選択や再確認要求

ページを表示したこと、音声を最後まで再生したこと、回答しなかったことから理解状態を補完しない。顔、視線、表情、沈黙は取得せず、API、保存形式、教授判断の入力にも含めない。「わかった」は自己申告として保存するが、確認問題への正答には置き換えない。

## 保存と状態

`learning_evidence`は観測値を追記し、`automatic_judgment`、確定後の`final_judgment`、後から直す場合の`correction`を別々に持つ。確認問題は問題IDと学習目標IDへ結び付け、ライブ補足後の再回答には`linked_supplement_id`を付ける。誤答を消さず、補足前後の回答を別の証拠として残す。

教室へ返す学習目標ごとの状態は次の5種類に固定する。

| 状態 | 意味 |
| --- | --- |
| 未確認 | 問いによる確認がない。閲覧、対象選択、肯定的な自己申告だけでは変えない |
| 支援希望 | 質問または「助けて」が観測された |
| つまずきあり | 誤答または「もう一度」が観測された |
| この問いで確認 | 特定の確認問題でルーブリック条件を満たした |
| 追加確認が必要 | 同じ学習目標について確認とつまずきの証拠が併存する |

補足後に同じ確認問題へ正答した場合は「この問いで確認」を現在状態とする。補足前の誤答は履歴に残る。

## 教授行動

Course Packageの確認問題は教材作成時に難所と共通誤答を含めて配置され、授業ランタイムが該当Teaching Unitの直後に自動提示する。回答はその問題のルーブリックだけで判定する。選択式はルーブリックに含まれる正答選択肢、短答式は条件と典型誤答を照合し、確定できない場合は未確認のままにする。

次の観測があると、ランタイムは運営者の操作を待たずに既存の質問キューへ`pedagogy-trigger`を登録する。

- 確認問題の誤答
- 「助けて」または「もう一度」
- 同一学習目標の矛盾する証拠
- 次のTeaching Unitに必要な前提へのつまずき

質問キューは残り時間と前提依存を判定し、授業中に扱う1件を選ぶ。採用された内容は[ライブ補足と本編への再接続](./live-supplements.md)と同じ生成、5ゲート審査、1回再生成、保留、本編復帰を通る。補足後は確認問題を再提示し、回答が来るまで理解済みにしない。
