# 質問受付と優先キュー

受講者は教室画面で質問する箇所を選び、テキストを送る。サーバーはLLM処理を待たずに質問を保存・分類して応答する。回答となるライブ補足の生成と審査はIssue #14でこのキューへ接続する。

## 送信時に固定する情報

ブラウザーは質問文、選択中のscene ID、意味IDを送る。サーバーは参加トークンを検証し、次を保存する。

- セッションと匿名参加者ID
- Course Package IDと版
- scene IDと意味ID
- 最後に完了したTeaching Unit ID
- 受信時刻と原文

sceneと意味IDがその教材に存在し、互いに対応する場合だけ受け付ける。APIキーや参加トークンは質問テーブルに保存しない。質問文は最大1,000文字とし、Reactの文字列として表示してHTMLを実行しない。

## 重複統合

同じ意味IDに対する未回答質問だけを統合候補にする。質問をUnicode NFKCで正規化し、大文字小文字、空白、記号、定型的な依頼表現を除いた文字列が一致するか、文字2-gramのDice係数が0.72以上なら同じ意図とみなす。

同じ参加者が同じ質問を繰り返しても同意人数は増えない。別の参加者から同じ意図が届いた場合だけ人数を増やし、全端末へWebSocketで更新する。質問原文、固定した教材位置、同意した匿名参加者はSQLiteへ保存する。

## 優先順位と分類

未回答質問を受け取るたびに、次のスコアを再計算する。

| シグナル | スコア |
|---|---:|
| 次のTeaching Unitが必要とする前提 | +50 |
| 現在の学習目標と一致 | +30 |
| 同意人数 | 1人につき+12 |
| 待ち時間 | 1分につき+1、最大+30 |
| 同じ参加者の未回答質問が2件を超える | 超過1件につき-24 |

同点では受信時刻が早い質問を優先し、それも同じなら質問IDで決定する。残り時間が20秒以上なら最高順位の1件を「授業中に回答」、残りを「授業後に回答」にする。20秒未満なら全件を授業後へ回す。分類結果には理由と、学習目標、前提、人数、待ち時間、残り時間の判定値を保存する。

教室画面には質問本文、同意人数、「授業中に回答」または「授業後に回答」、その理由を表示する。再接続時も保存済みキューを返す。個人の確認問題への回答は質問キューへ含めず、他の受講者へ表示しない。

## API

`POST /api/classrooms/:code/questions` は教室参加トークンを必須とし、受領した集約質問と現在のキューを返す。受付処理はネットワーク境界を含む試験で1秒未満、100件の連続したドメイン受付でも各処理1秒未満であることを確認する。
